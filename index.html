安克创新 AI 应用架构战略
模型是弹药，记忆才是壁垒

Warren Wu / 2026.03
现状

大多数企业的 AI 落地
停在了"接模型"这一步

1

接 API 就完事

接入 GPT/Claude API，加个 Chat 界面，宣布"AI 赋能"。没有数据飞轮，没有持续进化。

2

RAG 即答案

文档切片 + 向量检索 + LLM 回答。但 RAG 是无状态的 -- 每次对话从零开始，不记得昨天的决策。

3

Agent 是新名词

把几个工具串起来叫 Agent。但没有决策上下文，Agent 就是"第一天上班的聪明实习生"。

Core Insight

AI 的竞争正在转移：
从谁的模型更聪明
到谁的 Context 更丰富

LLM 正在快速商品化。GPT、Claude、Gemini、DeepSeek 能力差距在缩小。
真正的壁垒是：谁能给 Agent 提供更好的决策记忆。

关键概念

安克需要的不是数据库
而是 Decision Trace

传统系统记录的

"某 ASIN 上周 ACoS 25%"

"黑五期间广告支出 $50K"

"竞品 B 的市场份额 15%"

只有 What -- 发生了什么
VS

Decision Trace 记录的

"ACoS 从 30% 降到 25%，因为砍掉了长尾词"

"黑五选高出价策略，因为去年低出价错过流量高峰"

"竞品 B 增长但利润下降，判断为价格战不跟进"

What + Why + Outcome -- 完整决策链路

Build Memory 第一步

给每个业务员工配一个 AI 工作伙伴

不是先建知识图谱，而是先让 Agent 跟人一起工作，在协作中自然累积上下文。

传统思路：先建库再用

花 6 个月整理历史数据、构建知识图谱、标注实体关系。

问题：工程量巨大、数据过时快、业务团队感知不到价值。

我的思路：边用边建

Day 1 给投放专员配一个 AI Agent，跟他一起做投放决策。

每次协作自动沉淀：决策背景、选择理由、执行结果。

W1
员工 + AI Agent 一起工作
Agent 辅助分析数据、生成投放方案，员工做最终决策
W4
Agent 开始"记住"这个员工的偏好和经验
协作上下文自动结构化为 Decision Trace，不需要人工标注
M3
组织级记忆自然形成
多个员工的 Agent 记忆汇聚 → Knowledge Graph 自底向上生长，而非自顶向下设计

核心理念：记忆不是一次性工程项目，而是在人机协作中持续生长的活体系统。

落地场景

安克三大 Agent 场景

⚡

智能投放 Agent

输入: "Nano 系列在欧洲市场推新品"

Agent 行为:

1. 调取历史 Nano 欧洲投放 Decision Trace

2. 参考去年同期品类竞争态势

3. 生成投放策略 + 预算分配

4. 执行投放 + 实时归因反馈

关键: 有历史决策记忆，不从零开始

🔎

数据洞察 Agent

输入: "分析 Q1 北美充电品类趋势"

Agent 行为:

1. 自然语言 -> SQL 查询多数据源

2. 对比知识图谱中的历史趋势

3. 关联竞品动态和市场事件

4. 生成洞察报告 + 建议动作

关键: 不只检索数据，还关联上下文

🌐

全球运营 Agent

输入: "日本市场有什么异常信号？"

Agent 行为:

1. 联邦化查询日本本地数据节点

2. 比对全球其他市场模式

3. 追溯类似异常的历史处理方式

4. 推荐应对策略 + 风险评估

关键: 数据主权合规 + 全局视野

全球化

数据主权分治：联邦化架构

安克在全球销售，但数据不能全球流通。解法：全局路由 + 本地处理。

Global Control Plane

功能: 统一查询路由、全局策略下发、聚合洞察汇总

特点: 只看到聚合数据和洞察摘要，不接触原始数据

模型: GPT / Claude / Gemini（海外节点）

China Data Node

功能: 中国区数据存储、本地 Agent 推理、PIPL 合规

特点: 数据不出境，只返回洞察结果（聚合/摘要）

模型: 通义千问 / DeepSeek / 智谱 GLM-4（国产部署）

Federated RAG: 全局路由查询 -> 本地节点处理 -> 返回洞察不传原始数据

合规 + 低延迟 + 全局视野，三者兼得
